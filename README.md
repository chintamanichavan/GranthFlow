# anyfile

A C++20 command-line tool that reads **and modifies** PDF, EPUB, Markdown, plain-text and arbitrary
binary files. No dependencies beyond zlib. Includes an engineering system design, both as a
document and as a Blender-generated 3D diagram.

## Build

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./tests/run_tests.sh build/anyfile      # 49 end-to-end checks
```

Requires CMake ≥ 3.16, a C++20 compiler (Apple clang / GCC 10+) and zlib (present on macOS).

## Usage

```
anyfile [--as pdf|epub|markdown|text|binary] <file> [command] [args...]
anyfile <file>            # info summary
anyfile <file> help       # commands available for that file's type
```

Every file type gets the byte-level commands. Text adds line editing; Markdown adds
structure; PDF adds page/metadata/text operations; EPUB adds chapter reading and editing.

| Scope | Commands |
|---|---|
| any file | `info` `hex [off] [len]` `strings [min]` `patch <off> <hex>` `patch-str <off> <text>` `truncate <len>` `append-bytes <hex>` |
| text, markdown | `show [a:b]` `lines [a:b]` `grep <re>` `count` `replace <old> <new> [--all]` `replace-regex <re> <repl> [--all]` `append <text>` `insert <n> <text>` `set-line <n> <text>` `delete <a[:b]>` |
| markdown | `render [--no-color]` `outline` `section <h>` `replace-section <h> <text>` `add-section <lvl> <h> [text]` `links` `toc` |
| pdf | `text [page] [--out f]` `pages` `meta` `object <n>` `set-meta <Key> <v>` `replace <old> <new> [--page n] [--all]` `add-page <text>` `add-note <page> <text>` `delete-page <n>` |
| epub | `text [chapter]` `chapters` `meta` `files` `cat <file>` `set-meta <key> <v>` `replace <old> <new> [--chapter n] [--all]` |

Modifying commands write in place (via temp file + rename). PDF and EPUB commands accept `--out <file>`
to write a copy instead. `\n` and `\t` escapes are honoured in text arguments.

### Examples

```sh
anyfile report.pdf text 3                       # text of page 3
anyfile report.pdf set-meta Title "Q3 Report"   # appends an incremental update
anyfile report.pdf replace "Draft" "Final" --all
anyfile report.pdf add-page 'Appendix\nGenerated by anyfile'
anyfile report.pdf add-note 1 "Please review the totals"
anyfile report.pdf delete-page 2 --out report-trimmed.pdf

anyfile book.epub chapters                      # reading order with titles
anyfile book.epub text 3                        # chapter 3 as plain text
anyfile book.epub replace "colour" "color" --all
anyfile book.epub set-meta title "Second Edition"

anyfile notes.md outline
anyfile notes.md replace-section Status 'Reader works.\nEditor works.'
anyfile notes.md render

anyfile config.txt replace-regex '^debug=.*' 'debug=false'
anyfile firmware.bin hex 0x100 64
anyfile firmware.bin patch 0x104 deadbeef
```

## What the PDF engine handles

- Cross-reference tables **and** cross-reference streams (with `/Prev` and hybrid `/XRefStm` chains)
- Object streams (`/ObjStm`), FlateDecode, ASCII85, ASCIIHex, PNG/TIFF predictors
- Broken files: wrong offsets or missing xref fall back to a full object scan
- Text extraction with `ToUnicode` CMaps, WinAnsi/MacRoman encodings, form XObjects
- Edits are written as standard incremental updates, so the original bytes are never rewritten
  and the file stays readable by any viewer (verified against Apple PDFKit)

Not handled: encrypted PDFs (detected, refused), LZW/JBIG2/DCT streams (images), font metrics
(so column layout flattens), text set in CID/subset fonts cannot be `replace`d.

## What the EPUB engine handles

- EPUB 2 and 3: `META-INF/container.xml` → package file → manifest and spine (reading order)
- Chapter titles from the EPUB 3 navigation document, else the EPUB 2 NCX, else the chapter's
  first heading
- XHTML to plain text: block elements become line breaks, lists get bullets, entities are decoded,
  `<script>`/`<style>`/`<head>` are skipped
- Own zip reader and writer on zlib (stored and deflated entries). On save, entries that did not
  change are copied byte for byte and `mimetype` stays first and uncompressed
- Checked against two Project Gutenberg books (EPUB 2 and EPUB 3, 0.7 and 23.7 MiB); rewritten
  archives verified with `unzip -t` and Python's `zipfile`

Not handled: DRM-protected books (encrypted chapters fail with an error), Zip64 archives (over
4 GiB or 65,534 files), UTF-16 chapters, images and styling (text only). `replace` cannot match
text that crosses a tag (part of it bold or italic) or a line break in the XHTML source.

## Mac desktop app

`mac/Anyfile.xcodeproj` is a SwiftUI document-based app over the same C++ engine. Open it in
Xcode and press Run; it signs to run locally, so no Apple developer account is needed.

- One window per file. Text and Markdown are edited in place (Markdown has a Preview toggle), PDFs
  render through PDFKit with the engine's extracted text alongside, EPUBs show a chapter list
  next to the chapter's text, anything else gets a hex view.
- The command bar at the bottom exposes every CLI command for the file's kind; results that change
  the file update the document with Undo support, and Save writes it back.
- `Anyfile --open <path>` opens a file from the command line.

Layout: `mac/Anyfile/Bridge` is the Objective-C++ bridge (the only place Swift meets C++),
`mac/Anyfile/*.swift` the document and engine wrapper, `mac/Anyfile/Views` the panes.
Tests: `mac/AnyfileTests` (engine bridge and document, 19 cases) and `mac/AnyfileUITests`
(opens real files and drives the window, 7 cases). Run them with Cmd-U in Xcode; UI tests need
Accessibility permission for the test runner the first time.

## Tests and measurements

```sh
cmake --build build && (cd build && ctest)   # 124 unit cases across 10 modules + 49 end-to-end
python3 tests/bench.py build/anyfile          # timings on generated 400-page PDF, 200-chapter EPUB, 50 MiB text, 50 MiB binary
```

## System design

- `design/SYSTEM_DESIGN.md` — layers, components, read/modify data flows, trade-offs.
- `design/OOP_DESIGN.md` — class diagram, responsibilities, patterns, invariants, extension points.
- `design/blender_system_design.py` — the architecture as a 3D layered block diagram in Blender.
- `design/blender_oop_design.py` — the class diagram in UML notation in Blender.
- `design/blender_ui_design.py` — the UI/UX design of the Mac app, ray-traced in Blender: a library
  where every file has a cover made from its contents, and one reading window with five actions.

```sh
blender -b -P design/blender_system_design.py -- --render design/system_design.png
blender -b -P design/blender_oop_design.py -- --render design/oop_design.png
blender -b -P design/blender_ui_design.py -- --render design/ui_design.png
blender -P design/blender_system_design.py          # open interactively and orbit
```

The scripts are data-driven: edit the lists at the top (`LAYERS`/`COMPONENTS`/`EDGES`,
`CLASSES`/`RELATIONS`) to redraw. The UI design is drawn by the `draw_*` and `cover_*` functions. Rendered with Blender 5.2 using the Workbench engine.

## Layout

```
src/main.cpp          CLI
src/core/             FileHandler interface, ByteHandler base, registry, util
src/handlers/         text, markdown, pdf, epub handlers
src/pdf/              lexer, parser, object model, filters, document (xref + save), text extraction
src/epub/             zip archive, XML tokenizer, book (package, spine, chapter text, edits)
mac/                  SwiftUI app, Objective-C++ bridge, XCTest and XCUITest targets
tests/unit/           unit tests, one executable per module
tests/run_tests.sh    end-to-end smoke tests
tests/bench.py        timings on large generated files
design/               system design doc + Blender script
```
